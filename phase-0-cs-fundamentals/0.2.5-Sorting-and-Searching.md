## 1. Tổng Quan Sorting

| Algorithm          | Best       | Average    | Worst      | Space    | Stable? | In-place? |
| ------------------ | ---------- | ---------- | ---------- | -------- | ------- | --------- |
| **Bubble Sort**    | O(n)       | O(n²)      | O(n²)      | O(1)     | ✅      | ✅        |

| **Merge Sort**     | O(n log n) | O(n log n) | O(n log n) | O(n)     | ✅      | ❌        |

## 2. O(n²) Sorts — Cơ Bản

### Insertion Sort — ĐƠN GIẢN NHẤT & THỰC TẾ NHẤT trong nhóm O(n²)

```javascript
function insertionSort(arr) {
  for (let i = 1; i < arr.length; i++) {
    const key = arr[i];
    let j = i - 1;
    // Dịch chuyển elements lớn hơn key sang phải
    while (j >= 0 && arr[j] > key) {
      arr[j + 1] = arr[j];
      j--;
    }
    arr[j + 1] = key;
  }
  return arr;
}
// Best case O(n): nearly sorted array → chỉ cần vài lần dịch
// Thực tế: rất nhanh cho n < 50 → được dùng làm base case cho Merge/Quick Sort!
```

```
Ví dụ Insertion Sort:
  [5, 2, 4, 6, 1, 3]
   ^sorted|unsorted^

  i=1: key=2, insert vào vị trí đúng → [2, 5, 4, 6, 1, 3]
  i=2: key=4                          → [2, 4, 5, 6, 1, 3]
  i=3: key=6 (đã đúng vị trí)        → [2, 4, 5, 6, 1, 3]
  i=4: key=1, dịch tất cả             → [1, 2, 4, 5, 6, 3]
  i=5: key=3                          → [1, 2, 3, 4, 5, 6] ✓
```

## 3. O(n log n) Sorts — Hiệu Quả

### 3.1 Merge Sort — Stable, Guaranteed O(n log n)

**Ý tưởng**: Divide and Conquer — chia đôi, sort từng nửa, merge lại.

```
       [38, 27, 43, 3, 9, 82, 10]
              /              \
     [38, 27, 43]       [3, 9, 82, 10]
       /      \            /        \
   [38]  [27, 43]     [3, 9]    [82, 10]
          /    \        /  \      /    \
        [27]  [43]    [3]  [9] [82]  [10]
              MERGE ↑
        [27, 43]      [3, 9]    [10, 82]
              MERGE ↑
     [27, 38, 43]       [3, 9, 10, 82]
                 MERGE ↑
       [3, 9, 10, 27, 38, 43, 82]
```

```javascript
function mergeSort(arr) {
  if (arr.length <= 1) return arr;
  const mid = Math.floor(arr.length / 2);
  const left = mergeSort(arr.slice(0, mid));
  const right = mergeSort(arr.slice(mid));
  return merge(left, right);
}

function merge(left, right) {
  const result = [];
  let i = 0,
    j = 0;
  while (i < left.length && j < right.length) {
    if (left[i] <= right[j])
      result.push(left[i++]); // ≤ giữ stability
    else result.push(right[j++]);
  }
  return [...result, ...left.slice(i), ...right.slice(j)];
}
// Time: O(n log n) — always
// Space: O(n) — cần merge buffer
// Stable: YES

// Tại sao O(n log n)?
// log n levels (chia đôi) × O(n) merge mỗi level = O(n log n)
```

### 3.2 Quick Sort — In-place, Fastest in Practice

**Ý tưởng**: Chọn pivot, partition array thành [< pivot, pivot, > pivot], sort từng nửa.

```javascript
function quickSort(arr, low = 0, high = arr.length - 1) {
  if (low >= high) return arr;
  const pivotIdx = partition(arr, low, high);
  quickSort(arr, low, pivotIdx - 1);
  quickSort(arr, pivotIdx + 1, high);
  return arr;
}

function partition(arr, low, high) {
  const pivot = arr[high]; // chọn phần tử cuối làm pivot
  let i = low - 1; // boundary of "< pivot" region
  for (let j = low; j < high; j++) {
    if (arr[j] < pivot) {
      i++;
      [arr[i], arr[j]] = [arr[j], arr[i]]; // swap vào vùng nhỏ
    }
  }
  [arr[i + 1], arr[high]] = [arr[high], arr[i + 1]]; // đặt pivot vào vị trí
  return i + 1;
}

// Average: O(n log n) — nhanh nhất trong thực tế (cache-friendly!)
// Worst: O(n²) — khi pivot luôn là min/max (sorted array + pick last)
// Fix: randomized pivot hoặc median-of-three
```

```
Partition example (pivot = 5):
  [8, 3, 7, 1, 5]
                ^pivot

  j=0: 8≥5 → skip
  j=1: 3<5 → swap → [3, 8, 7, 1, 5], i=0
  j=2: 7≥5 → skip
  j=3: 1<5 → swap → [3, 1, 7, 8, 5], i=1

  Đặt pivot: swap arr[2] và arr[4] → [3, 1, 5, 8, 7]
                                            ^pivot đúng vị trí!
  Tất cả bên trái < 5, bên phải > 5 ✓
```

|                   | Merge Sort                  | Quick Sort                      |
| ----------------- | --------------------------- | ------------------------------- |
| Worst case        | **O(n log n)**              | O(n²)                           |
| Average           | O(n log n)                  | O(n log n)                      |
| Space             | O(n)                        | **O(log n)**                    |
| Stable            | **✅**                      | ❌                              |
| In-place          | ❌                          | **✅**                          |

### 3.4 Heap Sort

```javascript
function heapSort(arr) {
  const n = arr.length;
  // Build max-heap
  for (let i = Math.floor(n / 2) - 1; i >= 0; i--) heapify(arr, n, i);
  // Extract max, đặt cuối, heapify lại
  for (let i = n - 1; i > 0; i--) {
    [arr[0], arr[i]] = [arr[i], arr[0]];
    heapify(arr, i, 0);
  }
  return arr;
}

function heapify(arr, n, i) {
  let largest = i;
  const left = 2 * i + 1,
    right = 2 * i + 2;
  if (left < n && arr[left] > arr[largest]) largest = left;
  if (right < n && arr[right] > arr[largest]) largest = right;
  if (largest !== i) {
    [arr[i], arr[largest]] = [arr[largest], arr[i]];
    heapify(arr, n, largest);
  }
}
// O(n log n) guaranteed. In-place. NOT stable.
// Ít dùng trong practice vì cache-unfriendly (jump around in array).
```

## 4. Non-Comparison Sorts — O(n)

### Counting Sort — Khi biết range giá trị

```javascript
function countingSort(arr) {
  const max = Math.max(...arr);
  const count = new Array(max + 1).fill(0);

  for (const num of arr) count[num]++;

  let idx = 0;
  for (let i = 0; i <= max; i++) {
    while (count[i] > 0) {
      arr[idx++] = i;
      count[i]--;
    }
  }
  return arr;
}
// O(n + k) time, O(k) space — k = range of values
// Chỉ tốt khi k không quá lớn (ví dụ: sort ages 0-150)
```

## 5. Binary Search — Master Template

### 5.1 Classic Binary Search

```javascript
function binarySearch(arr, target) {
  let left = 0,
    right = arr.length - 1;
  while (left <= right) {
    const mid = left + Math.floor((right - left) / 2); // tránh overflow
    if (arr[mid] === target) return mid;
    if (arr[mid] < target) left = mid + 1;
    else right = mid - 1;
  }
  return -1; // not found
}
// O(log n) — mỗi bước loại bỏ 1/2 search space
```

### 5.2 Template cho mọi biến thể

```javascript
// Tìm vị trí INSERT (leftmost position where condition is true)
function lowerBound(arr, target) {
  let left = 0,
    right = arr.length;
  while (left < right) {
    const mid = left + Math.floor((right - left) / 2);
    if (arr[mid] < target) left = mid + 1;
    else right = mid;
  }
  return left; // first element >= target
}

// Tìm rightmost element ≤ target
function upperBound(arr, target) {
  let left = 0,
    right = arr.length;
  while (left < right) {
    const mid = left + Math.floor((right - left) / 2);
    if (arr[mid] <= target) left = mid + 1;
    else right = mid;
  }
  return left - 1; // last element <= target
}
```

### 5.3 Binary Search on Answer — Pattern rất mạnh

```javascript
// Bài: Koko ăn chuối (LC #875)
// Tìm tốc độ ăn nhỏ nhất để ăn hết trong h giờ
function minEatingSpeed(piles, h) {
  let left = 1,
    right = Math.max(...piles);
  while (left < right) {
    const mid = left + Math.floor((right - left) / 2);
    const hoursNeeded = piles.reduce((sum, p) => sum + Math.ceil(p / mid), 0);
    if (hoursNeeded <= h)
      right = mid; // có thể giảm tốc độ
    else left = mid + 1; // cần tăng tốc độ
  }
  return left;
}
// Binary search trên ANSWER SPACE, không phải trên array!
// Pattern: "tìm giá trị nhỏ nhất/lớn nhất thỏa condition"
```

## 6. Câu Hỏi Phỏng Vấn

**Q: Khi nào dùng Merge Sort vs Quick Sort?**

> A: **Quick Sort** cho general-purpose array sorting (nhanh nhất in practice nhờ cache locality). **Merge Sort** khi cần stability, worst-case guarantee, hoặc sorting linked lists (no random access → QS kém). External sorting (data lớn hơn RAM) dùng Merge Sort.

**Q: Tại sao `Array.sort()` của JS dùng TimSort?**

> A: TimSort = hybrid Merge Sort + Insertion Sort. Tận dụng "runs" (subsequences đã sorted) trong real-world data. Best case O(n) cho nearly sorted data. Stable. V8 chuyển từ Quick Sort sang TimSort vì stability guarantee (ES2019 spec yêu cầu stable sort).

**Q: Binary Search có bao nhiêu biến thể?**

> A: (1) Classic — tìm exact value, (2) Lower Bound — first ≥ target, (3) Upper Bound — first > target, (4) Rotated Array, (5) Search on Answer — minimize/maximize over condition, (6) Matrix Search. Template core giống nhau, chỉ thay đổi condition.

### 7.2 Direct Search — Tìm Kiếm Trực Tiếp

```
THUẬT TOÁN DIRECT SEARCH (Brute Force):

  Tìm pattern "lila" trong text "lililila":

  Text:     l i l i l i l a
  Pattern:  l i l a
            ↑ ↑ ↑ ✗  → THẤT BẠI ở vị trí 3

  Dịch S += 1:
  Text:     l i l i l i l a
              l i l a
              ✗         → THẤT BẠI ngay vị trí 0

  Dịch S += 1:
  Text:     l i l i l i l a
                l i l a
                ↑ ↑ ↑ ✗  → THẤT BẠI
  ...
  Dịch đến S = 4:
  Text:     l i l i l i l a
                      l i l a
                      ↑ ↑ ↑ ↑  → TÌM THẤY!

THUẬT TOÁN:
  1. So sánh pattern[0..m-1] với text[S..S+m-1]
  2. Nếu KHỚP tất cả → tìm thấy!
  3. Nếu THẤT BẠI ở bất kỳ vị trí → S += 1, bắt đầu lại

COMPLEXITY: O(n × m)
  n = length(text), m = length(pattern)
```

```
TẠI SAO KHÔNG THỂ TIẾP TỤC TỪ VỊ TRÍ THẤT BẠI?

  Tìm "lilila" trong "lilililas":

  l i l i l i l a s
  l i l i l a
  ↑ ↑ ↑ ↑ ↑ ✗   → thất bại ở vị trí 5

  Nếu tiếp tục từ vị trí 5 → BỎ QUA kết quả!
  Vì "lilila" bắt đầu từ vị trí 2:

  l i [l i l i l a] s
       ↑ kết quả thật nằm ở đây!

  → PHẢI quay lại S += 1 → O(n × m) là KHÔNG TRÁNH ĐƯỢC
     trong brute force!
  → CẦN thuật toán THÔNG MINH HƠN!
```

### 7.3 KMP — Knuth-Morris-Pratt

```
KMP (Knuth-Morris-Pratt) Algorithm:

  → Tìm substring trong LINEAR TIME: O(n + m)!

Ý TƯỞNG CHÍNH:
  Direct Search: thất bại → quay lại S += 1 (mất hết tiến trình)
  KMP: thất bại → KHÔNG quay lại đầu!
       → Nhảy đến vị trí I - maxPrefix(pattern)

  "maxPrefix" = PREFIX FUNCTION:
  → Tính TRƯỚC cho pattern
  → Với mỗi vị trí i: tìm đoạn KHỚP dài nhất
     mà CŨNG LÀ prefix của pattern

  Ví dụ: pattern "ABCABD"
  Prefix function: [0, 0, 0, 1, 2, 0]
                    A  B  C  A  B  D

  Nếu thất bại ở 'D' (vị trí 5):
  → prefix[4] = 2 → đã khớp "AB" (cũng là prefix)
  → Nhảy đến vị trí 2 thay vì quay lại 0!

  ┌──────────────────────────────────────────────────────┐
  │  KHÔNG CẦN implement ngay!                           │
  │  Chỉ cần NHỚ:                                       │
  │  → Direct search: O(n × m)                           │
  │  → KMP: O(n + m) — LINEAR!                           │
  │  → KMP phải build prefix function TRƯỚC               │
  │  → Có NHIỀU string search algorithms khác:            │
  │     Boyer-Moore, Rabin-Karp,...                        │
  └──────────────────────────────────────────────────────┘
```

### 7.4 Trie — Tìm NHIỀU Pattern Cùng Lúc

```
VẤN ĐỀ MỚI: tìm KHÔNG CHỈ 1 mà TẬP HỢP substrings!

  Tìm {"he", "she", "his", "hers"} trong text?
  → Dùng KMP cho từng pattern: O(n × k) — k = số patterns
  → CÓ CÁCH TỐT HƠN!

TRIE (Prefix Tree):
  → Rooted directed tree
  → Root = "empty string"
  → Mỗi EDGE = 1 ký tự
  → Đường đi root → node = 1 từ (hoặc prefix)
  → Terminal nodes [*] = "từ hoàn chỉnh"

  Trie cho {"he", "she", "his", "hers"}:

                (root)
               /      \
              h        s
             / \        \
            e   i       h
           / \   \       \
         [*] r   s[*]    e[*]
              \
              s[*]

  [*] = terminal node
  Paths: h→e = "he", h→e→r→s = "hers",
         h→i→s = "his", s→h→e = "she"
```

```
TÌM KIẾM BẰNG TRIE:

  Duyệt text từng ký tự:
  1. Bắt đầu từ ROOT
  2. Ký tự hiện tại có edge từ node hiện tại?
     CÓ → đi theo edge, tiếp tục ký tự tiếp
     KHÔNG → quay lại root, dịch vị trí +1
  3. Đến terminal node [*]? → TÌM THẤY pattern!

  → Tìm NHIỀU patterns cùng lúc!
  → Nhưng... vẫn O(n × m) trong worst case
     (mỗi lần thất bại phải quay lại root)
  → Cần kết hợp với KMP → AHO-CORASICK (§7.8)
```

### 7.7 Finite State Machine (FSM)

```
FINITE STATE MACHINE (Máy trạng thái hữu hạn):

  Một "thiết bị" có:
  → INPUT (đầu vào)
  → OUTPUT (đầu ra)
  → MEMORY (bộ nhớ)
  → INTERNAL STATE (trạng thái nội bộ)
  → TRANSITIONS (chuyển đổi giữa các trạng thái)

  Terminal state = KHÔNG có transitions tiếp
  Deterministic FSM (DFA) = MỌI transition duy nhất

BIỂU DIỄN FSM:

  1. GRAPH (đồ thị trạng thái):

     [Tính toán] ──gửi──→ [Sản xuất] ──xong──→ [Hoàn thành]
          |                    |
          └─────hủy──→ [Đã hủy]
                          └──retry──→ [Hoàn thành]

  2. TRANSITION TABLE:

     ┌──────────┬────────────┬──────────────┬──────────┐
     │ Input    │ State      │ Next State   │ Output   │
     ├──────────┼────────────┼──────────────┼──────────┤
     │ gửi      │ Tính toán  │ Sản xuất     │ start    │
     │ xong     │ Sản xuất   │ Hoàn thành   │ done     │
     │ hủy      │ Tính toán  │ Đã hủy       │ cancel   │
     │ retry    │ Đã hủy     │ Hoàn thành   │ restart  │
     └──────────┴────────────┴──────────────┴──────────┘

  MỌI algorithm = FSM! CPU operation = FSM khổng lồ!

  ỨNG DỤNG FSM TRONG FRONTEND/BACKEND:
  → Regex engine = FSM!
  → Parser (HTML, JSON, CSS) = FSM!
  → Game logic, UI wizard, workflow engine
  → Redux reducers = simplified FSM!
  → XState library = FSM framework cho JS!
```

### 7.8 Aho-Corasick — Linear Multi-Pattern Search

```
KẾT HỢP TRIE + KMP = AHO-CORASICK!

  VẤN ĐỀ: Trie + Direct Search = O(n × m) worst case
  GIẢI PHÁP: Build FSM trên Trie → LINEAR TIME!

Ý TƯỞNG:
  → Giống KMP: khi thất bại, KHÔNG quay lại đầu!
  → Mỗi node (trừ root) có SUFFIX LINK:
     trỏ đến node = longest proper suffix tồn tại trong Trie

  Trie {"he", "she", "his", "hers"} + Suffix Links:

    (root)
   /      \
  h        s             SUFFIX LINKS (→):
 / \        \            e(he) ──→ root
e   i       h            i(hi) ──→ root
|    \       \           e(she)──→ e(he)  ← "e" là suffix!
r    s[*]    e[*]        r(her)──→ root
|                        s(hers)─→ s(his) ← "s" là suffix!
s[*]

  KHI TÌM KIẾM:
  → Match edge? → đi theo edge
  → KHÔNG match? → đi theo SUFFIX LINK!
     (giống KMP nhảy đến maxPrefix)
  → Terminal node? → TÌM THẤY!
```

```
COMPLEXITY AHO-CORASICK:

  Build FSM: O(Σm) = tổng length tất cả patterns
  Search:    O(n + z) = LINEAR! (z = số kết quả)

  ┌───────────────────────────────────────────────────────┐
  │  SO SÁNH:                                             │
  │                                                       │
  │  1 pattern:                                           │
  │    Direct Search:  O(n × m)                           │
  │    KMP:            O(n + m) ← LINEAR                  │
  │                                                       │
  │  k patterns:                                          │
  │    Direct Search:  O(n × Σm)                          │
  │    Aho-Corasick:   O(n + Σm + z) ← LINEAR!           │
  │                                                       │
  │  → 1 pattern → dùng KMP (đơn giản hơn)               │
  │  → Nhiều patterns → dùng Aho-Corasick                 │
  │  → Phải build FSM TRƯỚC → tốn thời gian + memory     │
  └───────────────────────────────────────────────────────┘
```

### 7.9 Tóm Tắt — String Search & FSM

```
╠══════════════════════════════════════════════════════════════╣
```

## 8. CS Frontend: Grammars & Regular Expressions

> 📺 Nguồn: CS Frontend — Grammars, Regular Expressions

### 8.1 Vấn Đề — Tìm Theo "Pattern"

```
NHỚ LẠI: tìm kiếm trong string KHÔNG đơn giản!

  Nhưng thường ta KHÔNG tìm substring CỤ THỂ,
  mà tìm string KHỚP VỚI MỘT "PATTERN"!

  Ví dụ: "Subject: purchasing a license. Date: 21.10.2019"
  → Trích xuất text sau "Subject:" và "Date:"
  → KHÔNG biết trước NỘI DUNG cụ thể!

  → Cần 1 NGÔN NGỮ để mô tả pattern!
  → Cần DSL (Domain-Specific Language)!
```

### 8.2 DSL — Domain-Specific Language

```
DSL = ngôn ngữ được THIẾT KẾ cho 1 bài toán CỤ THỂ:

  ┌──────────────┬────────────────────────────────────┐
  │ DSL          │ Bài toán                           │
  ├──────────────┼────────────────────────────────────┤
  │ SQL          │ Truy vấn database                  │
  │ HTML         │ Cấu trúc trang web                 │
  │ CSS          │ Styling                            │
  │ Regex        │ Tìm kiếm/thay thế trong strings   │
  └──────────────┴────────────────────────────────────┘

  → REGULAR EXPRESSIONS (Regex) = DSL cho string pattern matching!
```

### 8.3 Grammars — Phân Loại

```
NGÔN NGỮ là gì (formal definition)?
  → Alphabet (bảng chữ cái) → tạo WORDS (từ)
  → Words → tạo SENTENCES (câu) theo RULES
  → GRAMMAR = mô tả formalized của ngôn ngữ + rules

4 LỚP GRAMMAR (Chomsky Hierarchy):

  ┌─────────────────────────────────────────────────────────────┐
  │  Type 0: Unrestricted         → Turing Machine             │
  │    ↑ phức tạp nhất                                         │
  │  Type 1: Context-Sensitive    → Linear-bounded automaton   │
  │                                                             │
  │  Type 2: CONTEXT-FREE         → Pushdown automaton         │
  │    → Phổ biến nhất trong programming!                      │
  │    → Mô tả syntax của hầu hết ngôn ngữ lập trình         │
  │                                                             │
  │  Type 3: REGULAR              → Finite State Machine       │
  │    ↓ đơn giản nhất                                         │
  │    → Regular Expressions thuộc lớp này!                    │
  └─────────────────────────────────────────────────────────────┘

  → MỖI lớp là SUBSET của lớp phức tạp hơn
  → Regular ⊂ Context-Free ⊂ Context-Sensitive ⊂ Unrestricted
```

### 8.4 Context-Free Grammar & BNF

```
CONTEXT-FREE GRAMMAR (CFG):
  → Chia grammar thành PRODUCTIONS (quy tắc sản xuất)
  → Phần phức tạp = tổ hợp các phần đơn giản
  → HỖ TRỢ RECURSION trong rules!
  → Mô tả syntax hầu hết programming languages

BNF (Backus-Naur Form) — ký hiệu CFG:

  Ví dụ: parse số thực "-124.24001E+35"

  <Number>    ::= [<Sign>] <digit> {<digit>}
                  [<Separator> <digit> {<digit>}]
                  [<Exponent> [<Sign>] <digit> {<digit>}]

  <digit>     ::= '0' | '1' | '2' | ... | '9'
  <Sign>      ::= '+' | '-'
  <Separator> ::= '.'
  <Exponent>  ::= 'E' | 'e'

  Giải thích:
  [] = optional (có hoặc không)
  {} = lặp lại 0+ lần
  |  = hoặc (alternation)
  ::= = "được định nghĩa là"

  → Đệ quy: <Number> có thể chứa <digit>,
     <digit> có thể là 1 trong 10 ký tự
  → Parser (JSON, HTML, JS) = implement CFG!
```

### 8.5 Regular Grammar & Regex

```
REGULAR GRAMMAR:
  → Lớp đơn giản NHẤT
  → Mỗi bước sinh ĐÚng 1 character
  → Được nhận dạng bởi FINITE STATE MACHINE (FSM)!
  → REGULAR EXPRESSIONS = mô tả regular grammar!

  ┌──────────────────────────────────────────────────────┐
  │  QUAN TRỌNG:                                         │
  │  → Syntax hầu hết programming languages              │
  │    KHÔNG THỂ mô tả bằng regular grammar!             │
  │    (cần context-free → CFG)                          │
  │  → Regex CHỈ mô tả được REGULAR languages            │
  │  → Ví dụ: regex KHÔNG THỂ match nested parentheses   │
  │    ((())()) — cần đếm depth → cần stack → cần CFG!  │
  └──────────────────────────────────────────────────────┘

REGEX = DSL cho REGULAR GRAMMAR:
  "№ 123456" và "№ 642" → pattern: /№ \d+/

  \d = [0-9] (Arabic numeral)
  +  = quantifier: 1 đến ∞ lần lặp
```

### 8.9 Regex Syntax — Escaping & Anchors

### 8.10 Regex Syntax — Quantifiers

```
QUANTIFIERS (bộ đếm lặp):

  ┌──────────┬────────────────────┬──────────────────────┐
  │ Syntax   │ Nghĩa              │ Ví dụ                │
  ├──────────┼────────────────────┼──────────────────────┤
  │ {n}      │ Đúng n lần         │ /\d{4}/ → "2019"     │
  │ {n,m}    │ Từ n đến m lần     │ /\d{2,3}/ → "21"     │
  │ {n,}     │ Từ n đến ∞ lần     │ /\d{1,}/ → "12345"   │
  │ *        │ = {0,} (0+ lần)    │ /ab*c/ → "ac","abbc" │
  │ +        │ = {1,} (1+ lần)    │ /ab+c/ → "abc","abbc"│
  │ ?        │ = {0,1} (optional) │ /colou?r/ → cả 2     │
  └──────────┴────────────────────┴──────────────────────┘

  Quantifier áp dụng cho:
  → 1 character:    /a{3}/  → "aaa"
  → 1 character set: /[a-z]+/ → "hello"
  → 1 group:        /(ab){2}/ → "abab"
```

```
GREEDY vs LAZY (tham lam vs lười):

  GREEDY (mặc định): tìm match DÀI NHẤT có thể

    /[a-z ]+end/  applied to "Begin end end end"
                   match: "egin end end end"
                          ↑ dài nhất! (greedy)

  LAZY (thêm ?): tìm match NGẮN NHẤT có thể

    /[a-z ]+?end/ applied to "Begin end end end"
                   match: "egin end"
                          ↑ ngắn nhất! (lazy)

  ┌──────────┬──────────────────────────┐
  │ Greedy   │ Lazy                     │
  ├──────────┼──────────────────────────┤
  │ *        │ *?                       │
  │ +        │ +?                       │
  │ {n,m}    │ {n,m}?                   │
  └──────────┴──────────────────────────┘

  → Mặc định = GREEDY!
  → Thêm ? sau quantifier = LAZY
```

### 8.11 Regex — Capture Groups

```javascript
// CAPTURE GROUPS — trích xuất fragments!
// Mỗi () tạo 1 group, đánh số từ 1

const text = "Date: 21.10.2019, Subject: license";
const regex = /Date: (\d{2}\.\d{2}\.\d{4}), Subject: (.+)/;
const match = text.match(regex);

// match[0] = "Date: 21.10.2019, Subject: license" (full match)
// match[1] = "21.10.2019" (group 1 — date)
// match[2] = "license"    (group 2 — subject)

// NAMED GROUPS (ES2018) — tên thay vì số:
const regex2 = /Date: (?<date>\d{2}\.\d{2}\.\d{4}), Subject: (?<subj>.+)/;
const match2 = text.match(regex2);
// match2.groups.date = "21.10.2019"
// match2.groups.subj = "license"

// REPLACE với groups:
"2019-10-21".replace(/(\d{4})-(\d{2})-(\d{2})/, "$3/$2/$1");
// → "21/10/2019"  ($1 = year, $2 = month, $3 = day)
```

## 9. CS Frontend: Advanced Regex & Assertions

> 📺 Nguồn: CS Frontend — Advanced Regular Expressions, Assertions

### 9.1 Backreferences — Tham Chiếu Ngược

```javascript
// BACKREFERENCE = tham chiếu đến group ĐÃ MATCH trong cùng regex!
// Dùng \1, \2,... để refer đến group theo index

// Ví dụ: tìm string trong quotes (cùng loại quote)
/(["']).*?\1/

// Giải thích:
// (["'])  → Group 1: match ' hoặc "
// .*?     → Lazy match bất kỳ ký tự nào (ít nhất có thể)
// \1      → PHẢI khớp với ĐÚNG ký tự mà Group 1 đã match!

// Test:
/(["']).*?\1/.exec('"hello"');    // match: "hello" ← cùng "
/(["']).*?\1/.exec("'world'");   // match: 'world' ← cùng '
/(["']).*?\1/.exec('"hello\'');   // NO match ← khác loại quote!

// NESTED backreference:
/((["']).*?)\2/
// Group 1 = toàn bộ content
// Group 2 = quote character
// \2 = match quote character giống Group 2
```

```
TẠI SAO CẦN BACKREFERENCE?

  ┌────────────────────────────────────────────────────────────┐
  │  KHÔNG có backreference:                                   │
  │  /["'].*?["']/  → match "hello' (SAI! khác loại quote!)  │
  │                                                            │
  │  CÓ backreference:                                         │
  │  /(["']).*?\1/  → CHỈ match khi open = close quote!       │
  │                                                            │
  │  Ứng dụng:                                                 │
  │  → Parse string literals trong code                        │
  │  → Tìm HTML tags: /<(\w+)>.*?<\/\1>/                      │
  │    (open tag phải match close tag!)                        │
  │  → Tìm từ lặp: /\b(\w+)\s+\1\b/                          │
  │    ("the the" → match!)                                    │
  └────────────────────────────────────────────────────────────┘
```

### 9.2 Named Backreferences

```javascript
// Khi có NHIỀU groups → index khó nhớ!
// → Dùng NAMED GROUPS + NAMED BACKREFERENCE

// Named group:     (?<name>...)
// Named backref:   \k<name>

// Ví dụ: tìm string trong quotes (named version)
/(?<q>["']).*?\k<q>/

// Giải thích:
// (?<q>["'])  → Named group "q": match ' hoặc "
// .*?         → Lazy match content
// \k<q>       → Backreference: phải khớp group "q"

// So sánh:
/(["']).*?\1/          // backreference by INDEX (khó đọc)
/(?<q>["']).*?\k<q>/   // backreference by NAME (dễ đọc!)

// Dùng named groups trong replace:
"2019-10-21".replace(
  /(?<y>\d{4})-(?<m>\d{2})-(?<d>\d{2})/,
  '$<d>/$<m>/$<y>'
);
// → "21/10/2019"
```

### 9.3 Non-Capturing Groups

```javascript
// MẶC ĐỊNH: mỗi () tạo 1 capturing group (đánh số, tốn memory)
// NẾU chỉ cần GROUPING mà KHÔNG cần capture → dùng (?:...)

// CAPTURING:
/Ru(ka|kav)/.exec("Ruka");
// match[0] = "Ruka", match[1] = "ka" ← group 1 captured!

// NON-CAPTURING:
/Ru(?:ka|kav)/.exec("Ruka");
// match[0] = "Ruka" ← KHÔNG có match[1]!

// TẠI SAO DÙNG?
// 1. Performance: không tốn memory lưu group
// 2. Clarity: groups chỉ chứa data CẦN THIẾT
// 3. Index: không làm lệch index các groups quan trọng
```

```
SO SÁNH 3 LOẠI GROUPS:

  ┌──────────────────┬────────────┬──────────┬──────────────┐
  │ Loại             │ Syntax     │ Capture? │ Dùng khi     │
  ├──────────────────┼────────────┼──────────┼──────────────┤
  │ Capturing        │ (...)      │ ✅ Có    │ Cần extract  │
  │ Named capturing  │ (?<n>...)  │ ✅ Có    │ Extract+name │
  │ Non-capturing    │ (?:...)    │ ❌ Không │ Chỉ grouping │
  └──────────────────┴────────────┴──────────┴──────────────┘
```

### 9.4 Lookahead & Lookbehind Assertions

```
ASSERTIONS = "nhìn trước/nhìn sau" mà KHÔNG consume characters!

  → Kiểm tra ký tự XUNG QUANH vị trí hiện tại
  → KHÔNG bao gồm trong match result!
  → KHÔNG tạo capturing group!

4 LOẠI ASSERTIONS:

  ┌──────────────────────┬────────────┬──────────────────────┐
  │ Assertion            │ Syntax     │ Nghĩa                │
  ├──────────────────────┼────────────┼──────────────────────┤
  │ Positive Lookahead   │ (?=...)    │ SAU vị trí CÓ ...    │
  │ Negative Lookahead   │ (?!...)    │ SAU vị trí KHÔNG ...  │
  │ Positive Lookbehind  │ (?<=...)   │ TRƯỚC vị trí CÓ ...  │
  │ Negative Lookbehind  │ (?<!...)   │ TRƯỚC vị trí KHÔNG...│
  └──────────────────────┴────────────┴──────────────────────┘
```

```javascript
// LOOKAHEAD — nhìn về phía TRƯỚC (→)

// Positive lookahead (?=...)
/\d+(?=€)/.exec("100€"); // match: "100" (số TRƯỚC €)
/\d+(?=€)/.exec("100$"); // NO match (không có € sau số)

// Negative lookahead (?!...)
/\d+(?!€)/.exec("100$"); // match: "100" (số KHÔNG theo sau bởi €)

// LOOKBEHIND — nhìn về phía SAU (←)

// Positive lookbehind (?<=...)
/(?<=\$)\d+/.exec("$100"); // match: "100" (số SAU $)
/(?<=hello)\s*world/.exec("hello world"); // match: " world"

// Negative lookbehind (?<!...)
/(?<!\$)\d+/.exec("€100"); // match: "100" (số KHÔNG phải sau $)
```

```
VÍ DỤ THỰC TẾ ASSERTIONS:

  1. Add commas to numbers (thousand separators):
     /\B(?=(\d{3})+(?!\d))/g
     "1234567".replace(regex, ",") → "1,234,567"

  2. Password validation (KHÔNG consume, chỉ CHECK):
     /^(?=.*[A-Z])(?=.*[0-9])(?=.*[!@#$]).{8,}$/
     → Ít nhất: 1 uppercase, 1 digit, 1 special, 8+ chars

  3. Extract price WITHOUT currency symbol:
     /(?<=\$|€|£)\d+(\.\d{2})?/
     "$19.99" → "19.99"

  ⚠️ Assertions KHÔNG tạo group!
     Nhưng có thể đặt nested groups BÊN TRONG assertion
```

### 9.5 Catastrophic Backtracking

```
"SLOW" REGULAR EXPRESSIONS — Catastrophic Backtracking!

  Một số regex khiến engine THỬ HÀNG TRIỆU combinations!

  Ví dụ nguy hiểm:
  /^(\d+)*$/  applied to "123456789!"

  Tại sao chậm?
  → (\d+)* = group lặp lại, BÊN TRONG group cũng lặp lại
  → Khi THẤT BẠI (vì "!"), engine thử MỌI cách chia:
     (123456789), (12345678)(9), (1234567)(89),
     (1234567)(8)(9), (123456)(789),...
  → Số combinations = EXPONENTIAL!

  ┌──────────────────────────────────────────────────────────┐
  │  ⚠️ CATASTROPHIC BACKTRACKING:                           │
  │  → Regex engine thử TẤT CẢ combinations khi thất bại   │
  │  → Time complexity: O(2^n) hoặc tệ hơn!                 │
  │  → Có thể FREEZE browser hoặc server!                   │
  │                                                          │
  │  PATTERN NGUY HIỂM:                                      │
  │  → Nested quantifiers: (a+)+, (a*)*                      │
  │  → Overlapping alternatives: (a|a)+                      │
  │  → Ambiguous patterns: (.*.*)+                           │
  └──────────────────────────────────────────────────────────┘
```

```javascript
// NGUY HIỂM:

// AN TOÀN — dùng lookahead + backreference:
/^(?=(\d+))\1*$/
// (?=(\d+)) → lookahead: capture digits nhưng KHÔNG backtrack!
// \1*       → match đúng cái đã capture

// CÁCH PHÒNG TRÁNH KHÁC:
// 1. Tránh nested quantifiers: (a+)+ → a+
// 2. Dùng possessive quantifiers (nếu engine hỗ trợ): a++

// 4. Test regex trước: regex101.com → xem steps count!
// 5. Set timeout cho regex operations

// ⚠️ BẢO MẬT: Attacker có thể gửi input khiến regex hang!
```

### 10.4 Parser Interface — TypeScript

```typescript
// TRẠNG THÁI CỦA PARSER:
enum ParserState {
  EXPECT_NEW_INPUT, // parser cần thêm input
}

// TOKEN = kết quả parse 1 phần tử
interface ParserToken<T = unknown> {
  type: string; // loại token: "string", "number", "boolean"...
  value?: T; // giá trị đã parse
}

// VALUE = kết quả cuối cùng
interface ParserValue<T = unknown> extends ParserToken<T> {}

// RESULT = [parsed value, remaining input]
type ParserResult<T = unknown> = [ParserValue, Iterable<string>];

// PARSER = generator function!
// → Nhận iterable input + previous value
// → Yield ParserState (cần input) hoặc ParserToken (kết quả)
// → Return [ParserValue, remaining input]
type Parser<T = unknown, R = unknown> = (
  iterable: Iterable<string>,
  prev?: ParserValue,
) => Generator<
  ParserState | ParserToken<T>, // yield type
  ParserResult<R>, // return type
  Iterable<string> | undefined // next() input type
>;
```

```
TẠI SAO DÙNG GENERATORS CHO PARSER?

  ┌──────────────────────────────────────────────────────┐
  │  1. LAZY: chỉ consume input khi CẦN (next())        │
  │  2. STATEFUL: generator giữ state giữa các yield    │
  │     → Giống FSM! Mỗi yield = 1 state transition    │
  │  3. COMPOSABLE: yield* delegate cho sub-parser       │
  │  4. BACKTRACKABLE: generator có thể dừng/bỏ dở     │
  │  5. STREAMABLE: parse input đến đâu, xử lý đến đó  │
  └──────────────────────────────────────────────────────┘
```

### 10.5 Combinators Cơ Bản

```
CÁC COMBINATOR CƠ BẢN:

  ┌──────────┬────────────────────────────────────────────────┐
  │ tag(s)   │ Match ĐÚNG string s                           │
  │          │ tag('"') → match dấu "                        │
  │          │ tag('true') → match literal "true"            │
  ├──────────┼────────────────────────────────────────────────┤
  │ take(r)  │ Match 1+ ký tự theo regex pattern r            │

  └──────────┴────────────────────────────────────────────────┘

  VÍ DỤ: Grammar → Combinator mapping:
  BNF:  <string> ::= '"' [^"]* '"'
```

### 10.6 JSON Parser — Từng Bước

```typescript
// 1. BOOLEAN: "true" | "false"
const boolean = or(tag("true"), tag("false"));
// BNF: <boolean> ::= 'true' | 'false'
// Dùng combinator: or()

// 2. STRING: '"' + content + '"'
const string = seq(tag('"'), take(/[^"]/), tag('"'));
// BNF: <string> ::= '"' [^"]* '"'
// Dùng combinators: seq() + tag() + take()

// 3. NUMBER: [sign] digits [.digits] [E [sign] digits]
const sign = take(/[\-+]/, { min: 0, max: 1 });

const exp = seq(
  tag([/e/i]), // 'E' hoặc 'e'
  take(/[\-+]/), // sign
  take(/\d/), // digits
);

const fractional = seq(
  tag("."), // dấu chấm
  take(/\d/), // digits sau dấu chấm
);

const number = seq(
  sign, // optional sign
  seq(
    or(
      seq(tag("0"), fractional), // 0.123
      seq(
        seq(tag([/[1-9]/]), take(/\d/, { min: 0 })), // 123
        opt(fractional), // optional .456
      ),
    ),
    opt(exp), // optional E+10
  ),
);
// Parse: "-124.24001E+35" ✓
// Parse: "0.5" ✓
// Parse: "42" ✓
```

```typescript
// 4. JSON = recursive composition!

// json = string | boolean | number | array | object
const json = (source: Iterable<string>, prev?: ParserValue | undefined) =>
  or(string, boolean, number, array, object)(source, prev);
// ⚠️ json phải là FUNCTION (không phải const)
// vì array/object tham chiếu NGƯỢC lại json! (recursion!)

// 5. ARRAY: '[' [json (',' json)*] ']'
const array = seq(
  tag("["),
  repeat(seq(json, tag(",")), { min: 0 }), // json, json, ...
  opt(json), // trailing element
  tag("]"),
);

// 6. OBJECT: '{' [key:value (',' key:value)*] '}'
const objectKey = seq(
  tag('"'),
  take(/[^"]/),
  tag('"'), // key = string
  tag(":"), // separator
);
const objectValue = seq(objectKey, json); // key: value

const object = seq(
  tag("{"),
  repeat(seq(objectValue, tag(",")), { min: 0 }),
  opt(objectValue),
  tag("}"),
);
```

```
JSON PARSER = SỰ KẾT HỢP CỦA TẤT CẢ:

  ┌─────────────────────────────────────────────────────────┐
  │  Grammar (BNF)     → CẤU TRÚC ngôn ngữ JSON           │
  │  Combinators        → MAP trực tiếp từ BNF rules       │
  │  FSM/Generators     → THỰC THI parsing step-by-step    │
  │  Iterators          → DUYỆT input lazily               │
  │  Recursion          → json ↔ array ↔ object            │
  └─────────────────────────────────────────────────────────┘

  Parse flow cho '{"name":"Alice","age":30}':

  object parser
   ├─ tag('{')      → match '{'
   ├─ objectValue
   │   ├─ objectKey
   │   │   ├─ tag('"') → match '"'
   │   │   ├─ take     → "name"
   │   │   ├─ tag('"') → match '"'
   │   │   └─ tag(':') → match ':'
   │   └─ json → string parser → "Alice"

   ├─ objectValue
   │   ├─ objectKey → "age"
   │   └─ json → number parser → 30
   └─ tag('}')      → match '}'
```
