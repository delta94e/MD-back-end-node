### 0.1 Tại Sao Cần Binary Search?

```
NHỚ LẠI ARRAY:

  ┌──────────────────────────────────────────────────────┐
  │  Operation                    │ Complexity           │
  ├──────────────────────────────────────────────────────┤
  │  Insert/Delete ở CUỐI         │ O(1)                │
  │  Insert/Delete ở VỊ TRÍ KHÁC  │ O(n) ← phải shift! │
  │  Truy cập theo index          │ O(1)                │
  │  TÌM KIẾM element bất kỳ     │ O(n) ← CHẬM!       │
  └──────────────────────────────────────────────────────┘

  Search O(n) = duyệt từng phần tử → CÓ CÁCH NHANH HƠN?
  → CÓ! Nhưng có ĐIỀU KIỆN: array phải SORTED!
```

```
BINARY SEARCH — Thuật toán tìm kiếm nhị phân:

  Ví dụ: tìm số 22 trong array đã sort:

  [2, 5, 8, 12, 16, 22, 28, 32, 36, 44, 48]
   ▲low              ▲mid                ▲high

  Bước 1: mid = 22? → 22 < 28? KHÔNG BẰNG
          mid(28) > 22 → thu hẹp sang TRÁI

  [2, 5, 8, 12, 16, 22]
   ▲low    ▲mid       ▲high

  Bước 2: mid = 12? → 12 < 22 → thu hẹp sang PHẢI

  [16, 22]
   ▲low▲mid▲high

  Bước 3: mid = 16? → 16 < 22 → sang PHẢI

  [22]
   ▲ = TÌM THẤY!

THUẬT TOÁN:
  1. Lấy element ở GIỮA array
  2. So sánh với target
  3. Nếu BẰNG → xong!
  4. Nếu nhỏ hơn target → thu hẹp sang NỬA PHẢI
  5. Nếu lớn hơn target → thu hẹp sang NỬA TRÁI
  6. Lặp lại

COMPLEXITY: O(log n) — LOGARITHMIC!
  → Tìm trong array 2^32 phần tử (~4 tỷ) = chỉ 32 phép so sánh!
```

```
ỨNG DỤNG THỰC TẾ CỦA BINARY SEARCH:

  ✅ Tìm kiếm trong sorted array (cơ bản)

  ✅ git bisect — tìm commit gây bug:
     → 1000 commits, bug xuất hiện ở đâu đó
     → Binary search: chỉ cần test ~10 commits!
     → git bisect start → git bisect bad → git bisect good

  ✅ Debug khi console "im lặng":
     → Đặt console.log() ở GIỮA code
     → Chạy → nếu in ra → bug ở NỬA SAU
     →         nếu không → bug ở NỬA TRƯỚC
     → Lặp lại → tìm bug cực nhanh!

  → Mỗi khi cần tìm kiếm, HỎI: data có sorted không?
    Nếu CÓ → dùng binary search!
```

### 0.2 Từ Array Đến Tree — Hành Trình

```
VẤN ĐỀ: Search nhanh rồi (O(log n)), nhưng INSERT/DELETE vẫn O(n)!

Array:      [1, 3, 5, 7, 9, 11, 13]
             Insert 6 ở giữa → phải SHIFT tất cả phần tử sau!
             → O(n) cho insert/delete

Linked List: 1 → 3 → 5 → 7 → 9 → 11 → 13
             Insert KHÔNG cần shift (chỉ nối pointers)
             → O(1) insert/delete!
             NHƯNG: binary search KHÔNG hoạt động
             (không truy cập giữa được — phải duyệt tuần tự)

THẾ NẾU ta SẮP XẾP linked list thành CẤU TRÚC CÂY?

     Bước biến đổi:

     1 → 3 → 5 → 7 → 9 → 11 → 13    (linked list)

                    ↓ reorganize

                    7                   (tree!)
                   / \
                  3   11
                 / \   / \
                1   5 9   13

     → Binary search TRÊN CÂY!
     → Insert/Delete chỉ cần nối lại pointers!
     → BEST OF BOTH WORLDS!
```

### 0.3 Thuật Ngữ Cây

```
CÂY (Tree) là gì?
  → Subtype của GRAPH
  → Connected (mọi node đều kết nối)
  → Acyclic (không có vòng lặp)
  → Giữa 2 vertices bất kỳ chỉ có ĐÚNG 1 path

ROOTED TREE (Cây có gốc):
  → Directed tree (có hướng)
  → 1 node duy nhất KHÔNG có arc đến = ROOT (gốc)
  → Từ root có đúng 1 path đến MỌI vertex

                    [ROOT] ← gốc
                   /      \
              [parent]   [parent] ← tổ tiên (ancestor)
              /     \
         [child]  [child] ← con (descendant)
          /
       [leaf]  ← lá (không có con)

  Edges = cạnh nối các nodes

ORDERED TREE (Cây có thứ tự):
  → Rooted tree + con cháu được SORT theo thứ tự
  → = SEARCH TREE!

BINARY TREE:
  → Mỗi node có TỐI ĐA 2 con (left, right)
  → Nếu > 2 con → MULTI-WAY TREE
```

### 0.4 BST Trong Memory

```typescript
// Tree = Graph → dùng cách biểu diễn graph
// Nhưng MATRIX quá thừa → dùng ADJACENCY STRUCTURE
// Binary tree → chỉ cần 2 references: left và right

interface BinaryNodeChildren<T> {
  left?: BinaryNode<T>;
  right?: BinaryNode<T>;
}

class BinaryNode<T> {
  value: T;
  parent: BinaryNode<T> | null;
  left: BinaryNode<T> | null;
  right: BinaryNode<T> | null;

  constructor(
    value: T,
    opts: { parent?: BinaryNode<T> } & BinaryNodeChildren<T> = {},
  ) {
    this.value = value;
    this.parent = opts.parent ?? null;
    this.left = opts.left ?? null;
    this.right = opts.right ?? null;
  }
}
```

```
INSERT VÀ DELETE TRONG BST:

  Đều BẮT ĐẦU bằng SEARCH!

  Search: so sánh value với node hiện tại:
    value < node → đi TRÁI
    value > node → đi PHẢI
    value = node → TÌM THẤY!

  INSERT: search đến cuối → chèn ở vị trí đúng
  DELETE: tìm node → thay bằng:
    → Phần tử LỚN NHẤT bên TRÁI (in-order predecessor)
    → HOẶC phần tử NHỎ NHẤT bên PHẢI (in-order successor)
```

### 0.5 Vấn Đề Cân Bằng & Self-Balancing Trees

```
TẤT CẢ operations hiệu quả CHỈ KHI cây BALANCED!

  Balanced:              Skewed (mất cân bằng):
       7                  1
      / \                  \
     3   11                 3
    / \   / \                \
   1   5 9   13               5
                               \
  Height: 3                     7
  Search: O(log n)               \
                                  9
                                Search: O(n) — thành linked list!

  → Insert 1,2,3,4,5 tuần tự → BST thành LINKED LIST!
  → Mọi insert/delete CÓ THỂ phá vỡ balance!
  → Cần SELF-BALANCING: tự cân bằng sau mỗi thao tác!
```

```
AVL TREE (Adelson-Velsky & Landis, 1962):
  → Self-balancing BST
  → |height(left) - height(right)| ≤ 1 cho MỌI node
  → Cân bằng bằng ROTATIONS (xoay cây)
  → ✅ Search NHANH (strictly balanced)
  → ❌ Insert/Delete CHẬM hơn (nhiều rotations)

RED-BLACK TREE:
  → Self-balancing BST
  → Mỗi node có MÀU (Red hoặc Black)
  → Cân bằng bằng rotations + đổi màu
  → ❌ Search chậm hơn AVL một chút
  → ✅ Insert/Delete NHANH hơn (ít rotations)
  → Dùng bởi: std::map (C++), TreeMap (Java), Linux CFS

  ┌────────────────┬─────────────────┬──────────────────────┐
  │                │ AVL             │ Red-Black            │
  ├────────────────┼─────────────────┼──────────────────────┤
  │ Balance        │ Strict (≤1)     │ Lỏng hơn (≤2×log)   │
  │ Search         │ ✅ Nhanh hơn   │ Chậm hơn chút       │
  │ Insert/Delete  │ Chậm hơn       │ ✅ Nhanh hơn        │
  │ Use case       │ Read-heavy      │ Write-heavy          │
  └────────────────┴─────────────────┴──────────────────────┘
```

```
║                                                                  ║
```

### 0.7 B-Tree — Multi-Way Tree

```
VẤN ĐỀ: Binary tree nodes rải rác → cache KÉM!
Giải pháp: mỗi node chứa ARRAY nhiều elements?

B-TREE:
  → Multi-way balanced search tree
  → Mỗi node chứa ARRAY of values (đã sort)
  → Mỗi node có NHIỀU children (không chỉ 2)

  Ví dụ B-tree bậc 3 (mỗi node tối đa 3 keys):

              [10 | 20]
             /    |    \
      [3|5|7]  [12|15] [25|30|40]

  → Load 1 node = load 1 BLOCK data
  → Cache-friendly (array liên tiếp trong node)
  → Load nodes ON DEMAND (không cần load tất cả)
  → Perfect cho LƯỢNG DATA KHỔNG LỒ

ỨNG DỤNG:
  → DATABASE INDEXES (MySQL InnoDB dùng B+ Tree!)
  → File systems (NTFS, ext4)
  → Bất kỳ đâu cần read/write lượng lớn data trên disk

B+ TREE (biến thể):
  → Tất cả data NẰM Ở LEAF nodes
  → Internal nodes chỉ chứa keys để navigate
  → Leaf nodes liên kết thành linked list → range queries cực nhanh
```

```
B-TREES vs BINARY TREES vs HASH TABLES:

  ┌──────────────────┬──────────────┬──────────────┬──────────────┐
  │                  │ B-Tree       │ Binary Tree  │ Hash Table   │
  ├──────────────────┼──────────────┼──────────────┼──────────────┤
  │ Cache            │ ✅ TỐT      │ ❌ Kém       │ ✅ Tốt      │
  │ Balanced         │ ✅ Luôn     │ Cần AVL/RB   │ N/A          │
  │ Disk-friendly    │ ✅ PERFECT  │ ❌ Không     │ ❌ Không    │
  │ Sorted iteration │ ✅ Có      │ ✅ Có        │ ❌ Không    │
  │ Extra memory     │ Nhiều ptrs  │ 2 ptrs/node  │ Ít           │
  │ Best for         │ Databases   │ In-memory    │ Key lookup   │
  │ Collisions       │ Không       │ Không        │ ⚠️ Có       │
  │ Growth           │ Tự balance  │ Cần rebalance│ Rehash       │
  └──────────────────┴──────────────┴──────────────┴──────────────┘

  → KHÔNG có data structure "lý tưởng"!
  → Chỉ có data structure PHÙ HỢP cho bài toán cụ thể.
```

### 0.9 Array-Based Binary Trees & Binary Heap

> 📺 Nguồn: CS Frontend — Array-Based Binary Trees & Binary Heap

```
BINARY TREE ≈ DOUBLY LINKED LIST!

  Doubly Linked List:       Binary Tree:
  ┌──────┐                  ┌──────┐
  │ prev │ ← pointer        │ left │ ← pointer
  │ value│                   │ value│
  │ next │ → pointer        │right │ → pointer
  └──────┘                  └──────┘

  → Thay prev/next bằng left/right!
  → Tất cả ưu/nhược điểm của linked list đều có:
     ✅ Insert/Delete linh hoạt (chỉ nối pointers)
     ❌ Nodes rải rác trên heap → cache KÉM
     ❌ Extra memory cho pointers

THẾ NẾU biểu diễn binary tree BẰNG ARRAY?
```

```
ARRAY-BASED BINARY TREE — CÔNG THỨC INDEX:

  Lưu tree vào ARRAY THƯỜNG, dùng CÔNG THỨC tính vị trí:

  Root = index 0
  Left child  = 2 * i + 1
  Right child = 2 * i + 2
  Parent      = Math.floor((i - 1) / 2)

  Ví dụ:
                14              Array: [14, 8, 19, 3, 10, 17, 25]
               /  \                     [0] [1] [2] [3] [4] [5] [6]
              8    19
             / \   / \
            3  10 17  25

  Kiểm tra:
  • Left child của root (i=0): 2×0+1 = 1 → arr[1] = 8 ✅
  • Right child của root: 2×0+2 = 2 → arr[2] = 19 ✅
  • Right child của node 8 (i=1): 2×1+2 = 4 → arr[4] = 10 ✅
  • Parent của node 10 (i=4): floor((4-1)/2) = 1 → arr[1] = 8 ✅

  → THỰC SỰ HOẠT ĐỘNG!
```

```
BST TRÊN ARRAY:

  ┌──────────────────────────────────────────────────────────┐
  │  Array-based BST:                                        │
  │  → Cache PERFECT! (array liên tiếp trong memory)        │
  │  → Search, Insert, Delete = O(log n)                    │
  │  → Nhưng cần VECTOR để mở rộng (giống array thường)    │
  └──────────────────────────────────────────────────────────┘

BINARY TREES KHÔNG CHỈ ĐỂ TÌM KIẾM:
  → Nén dữ liệu (Huffman Coding)
  → Implement cấu trúc dữ liệu khác
  → Priority Queue → BINARY HEAP!
```

```
PRIORITY QUEUE → BINARY HEAP:

  Priority Queue = hàng đợi ƯU TIÊN:
  → Thứ tự KHÔNG theo lượt vào
  → Mà theo TRỌNG SỐ (priority)!

  Cách naive: sort array sau mỗi lần insert → O(n log n) 💀

  BINARY HEAP = implementation HIỆU QUẢ:
  → Binary tree (KHÔNG phải search tree!)
  → Max-Heap: parent ≥ children (root = MAX)
  → Min-Heap: parent ≤ children (root = MIN)
  → Lấy root = O(1)!
  → Insert/Delete = O(log n)
  → Implement trên ARRAY (dùng công thức ở trên)

  Max-Heap ví dụ:
              100
             /    \
           19      36
          / \     / \
         17  3   25  1

  Array: [100, 19, 36, 17, 3, 25, 1]
  Rule:  Mỗi parent ≥ tất cả children của nó
```

```
HEAP OPERATIONS — TRỰC QUAN:

═══ DELETE (Extract Max/Min) ═══

  Bước 1: Lấy ROOT ra (= giá trị max)
            [100]  ← extract!
             /  \
           19    36

  Bước 2: Đưa phần tử CUỐI CÙNG lên root
            [1]   ← phần tử cuối lên thay
             /  \
           19    36

  Bước 3: SIFT DOWN — so sánh với children, swap nếu nhỏ hơn
            [1]          [36]         [36]
             /  \    →    /  \    →    /  \
           19   [36]    19   [1]     19   [25]
          / \   /      / \   /      / \   /
         17  3 25     17  3 25     17  3 [1]

  → Lặp cho đến khi đúng vị trí hoặc là leaf
  → Complexity: O(log n) (chiều cao cây)

═══ INSERT ═══

  Bước 1: Thêm element MỚI vào CUỐI array (cuối cây)

              100               100
             /    \            /    \
           19      36   →   19      36
          / \               / \     /
         17  3            17   3  [50] ← mới!

  Bước 2: SIFT UP — so sánh với parent, swap nếu lớn hơn

              100               100              [100]
             /    \            /    \            /    \
           19      36   →   19     [50]  →    19    [100]...
          / \     /         / \     /         / \     /
         17  3  [50]       17  3  [36]       17  3  [36]

  Lặp: 50 > 36? → swap!  50 > 100? → KHÔNG → dừng!

  → Complexity: O(log n)
```

```
HEAP SORT — Sắp xếp bằng Heap:

  ┌──────────────────────────────────────────────────────────────┐
  │  Heap Sort:                                                   │
  │  1. Build max-heap từ array → O(n)                           │
  │  2. Lặp: extract max → đặt cuối array → heapify → O(n log n)│
  │                                                               │
  │  ✅ KHÔNG BAO GIỜ degrade (luôn O(n log n))                 │
  │     (Quick Sort có thể degrade → O(n²)!)                     │
  │  ✅ Không cần extra memory (in-place)                        │
  │  ❌ UNSTABLE (không giữ thứ tự các phần tử bằng nhau)      │
  │  ❌ Trên array gần-sorted, vẫn chậm (không optimize được)  │
  │  ❌ Không thể parallelize                                    │
  │                                                               │
  │  ⚠️ JS KHÔNG có Heap built-in!                              │
  │  → Phải tự implement (hoặc dùng thư viện)                   │
  └──────────────────────────────────────────────────────────────┘
```

```
CÁC LOẠI HEAP KHÁC:

  Ngoài Binary Heap, còn có:

  ┌──────────────────┬────────────────────────────────────────┐
  │ Binomial Heap    │ Tập hợp binomial trees                │
  │                  │ Merge 2 heaps = O(log n) (nhanh hơn!) │
  │                  │ Dùng trong network algorithms          │

  │ Fibonacci Heap   │ Amortized O(1) insert + decrease-key  │
  │                  │ Tối ưu cho Dijkstra, Prim's MST       │
  │                  │ Phức tạp để implement                  │
  ├──────────────────┼────────────────────────────────────────┤
  │ Binary Heap      │ Đơn giản, hiệu quả, cache-friendly   │
  │                  │ Đủ tốt cho hầu hết use cases          │
  └──────────────────┴────────────────────────────────────────┘
```

## 1. Binary Tree — Cơ Bản

### 1.1 Cấu trúc

```
Mỗi node có tối đa 2 children: left và right.

           1             ← root
          / \
         2   3           ← children of 1
        / \   \
       4   5   6         ← leaves (lá): nodes không có children
      /
     7

Properties:
  - Depth (độ sâu): khoảng cách từ root. root = depth 0. Node 4 = depth 2.
  - Height (chiều cao): path dài nhất từ node đến leaf. root = height 3.
  - Total nodes: tối đa 2^(h+1) - 1 cho tree height h.
```

## 2. Tree Traversals — Duyệt Cây

### 2.1 Bốn cách duyệt

```
Cho tree:       1
               / \
              2   3
             / \
            4   5

Inorder   (Left → Root → Right):  4, 2, 5, 1, 3   ← BST: sorted order!
Preorder  (Root → Left → Right):  1, 2, 4, 5, 3   ← Dùng cho serialize
Postorder (Left → Right → Root):  4, 5, 2, 3, 1   ← Dùng cho delete
Level-order (BFS):                1, 2, 3, 4, 5    ← Theo từng tầng
```

### 2.2 Recursive Implementation

```javascript
// Inorder (quan trọng nhất cho BST)
function inorder(root, result = []) {
  if (!root) return result;
  inorder(root.left, result); // L
  result.push(root.val); // Root
  inorder(root.right, result); // R
  return result;
}

// Preorder
function preorder(root, result = []) {
  if (!root) return result;
  result.push(root.val); // Root
  preorder(root.left, result); // L
  preorder(root.right, result); // R
  return result;
}

// Postorder
function postorder(root, result = []) {
  if (!root) return result;
  postorder(root.left, result); // L
  postorder(root.right, result); // R
  result.push(root.val); // Root
  return result;
}
```

### 2.3 Iterative Inorder (dùng Stack)

```javascript
function inorderIterative(root) {
  const result = [],
    stack = [];
  let curr = root;
  while (curr || stack.length) {
    while (curr) {
      // đi sâu bên trái
      stack.push(curr);
      curr = curr.left;
    }
    curr = stack.pop(); // backtrack
    result.push(curr.val); // visit
    curr = curr.right; // chuyển sang phải
  }
  return result;
}
```

### 2.4 Level-Order (BFS dùng Queue)

```javascript
function levelOrder(root) {
  if (!root) return [];
  const result = [],
    queue = [root];
  while (queue.length) {
    const level = [];
    const size = queue.length; // fix size trước khi loop!
    for (let i = 0; i < size; i++) {
      const node = queue.shift();
      level.push(node.val);
      if (node.left) queue.push(node.left);
      if (node.right) queue.push(node.right);
    }
    result.push(level);
  }
  return result;
}
// [[1], [2,3], [4,5]] — mỗi inner array = 1 level
```

## 3. Binary Search Tree (BST)

### 3.1 BST Property

**Với mọi node**: tất cả nodes bên trái **< node** < tất cả nodes bên phải.

```
BST hợp lệ:          KHÔNG hợp lệ:
       8                    8
      / \                  / \
     3   10               3   10
    / \    \             / \    \
   1   6   14           1   6   14
      / \                  / \
     4   7                4   12  ← 12 > 8, phải ở phải 8!
```

### 3.2 BST Operations

```javascript
// SEARCH — O(log n) average, O(n) worst (skewed)
function search(root, target) {
  if (!root) return null;
  if (target === root.val) return root;
  if (target < root.val) return search(root.left, target);
  return search(root.right, target);
}

// INSERT — O(log n) average
function insert(root, val) {
  if (!root) return new TreeNode(val);
  if (val < root.val) root.left = insert(root.left, val);
  else if (val > root.val) root.right = insert(root.right, val);
  return root; // duplicate → ignore
}

// DELETE — O(log n) average — PHỨC TẠP NHẤT
function deleteNode(root, key) {
  if (!root) return null;
  if (key < root.val) {
    root.left = deleteNode(root.left, key);
  } else if (key > root.val) {
    root.right = deleteNode(root.right, key);
  } else {
    // Tìm thấy node cần xóa
    // Case 1 & 2: 0 hoặc 1 child
    if (!root.left) return root.right;
    if (!root.right) return root.left;
    // Case 3: 2 children → thay bằng inorder successor (nhỏ nhất bên phải)
    let successor = root.right;
    while (successor.left) successor = successor.left;
    root.val = successor.val;
    root.right = deleteNode(root.right, successor.val);
  }
  return root;
}
```

### 3.3 BST Big-O

| Operation | Average  | Worst (Skewed) |
| --------- | -------- | -------------- |
| Search    | O(log n) | O(n)           |
| Insert    | O(log n) | O(n)           |
| Delete    | O(log n) | O(n)           |
| Inorder   | O(n)     | O(n)           |

> **Worst case O(n)** xảy ra khi BST bị **skewed** (lệch) — insert 1,2,3,4,5 tuần tự → thành linked list! Giải pháp: **self-balancing trees** (AVL, Red-Black).

## 4. Self-Balancing Trees — AVL & Red-Black

### 4.1 AVL Tree

Duy trì |height(left) - height(right)| ≤ 1 cho **mọi node** bằng rotations.

```
4 loại rotation:

Right Rotation (LL case):       Left Rotation (RR case):
      z                   y           z                 y
     / \                / \          / \               / \
    y   T4   →         x   z       T1  y     →       z   x
   / \                / \ / \          / \           / \ / \
  x   T3             T1 T2 T3 T4     T2  x         T1 T2 T3 T4
 / \                                     / \
T1  T2                                  T3 T4

Left-Right (LR):                Right-Left (RL):
First left rotate on y,         First right rotate on y,
then right rotate on z          then left rotate on z
```

### 4.2 Red-Black Tree

Dùng "màu" (Red/Black) + 5 rules để đảm bảo balanced. **Less strict** hơn AVL — cho phép height chênh lệch gấp đôi.

**Quy tắc**: (1) Mỗi node là Red hoặc Black, (2) Root luôn Black, (3) Leaves (NIL) luôn Black, (4) Red node → children phải Black (no 2 consecutive reds), (5) Mọi path root→leaf có **cùng số Black nodes**.

|                | AVL                         | Red-Black                           |
| -------------- | --------------------------- | ----------------------------------- |
| Balance factor | ≤ 1                         | height ≤ 2 × log(n+1)               |
| Search         | Nhanh hơn (strict balanced) | Chậm hơn một chút                   |
| Insert/Delete  | Chậm hơn (nhiều rotations)  | Nhanh hơn (ít rotations)            |
| Dùng bởi       | Database indexes            | `std::map`, Java TreeMap, Linux CFS |

> **Interview level**: Biết tại sao cần self-balancing, hiểu concept rotation. KHÔNG cần implement AVL/RB tree from scratch (trừ Google).

## 5. Heap — Đống

### 5.1 Heap là gì

**Complete Binary Tree** thỏa mãn heap property:

- **Min-Heap**: parent ≤ children (root = minimum)
- **Max-Heap**: parent ≥ children (root = maximum)

```
Min-Heap:            Max-Heap:
       1                   9
      / \                 / \
     3   5               7   8
    / \ / \             / \ /
   7  8 9  6           4  5 6

Array representation (vì complete → contiguous):
Min-Heap: [1, 3, 5, 7, 8, 9, 6]
           0  1  2  3  4  5  6

Parent of i:       Math.floor((i - 1) / 2)
Left child of i:   2 * i + 1
Right child of i:  2 * i + 2
```

### 5.2 Heap Operations

```javascript
class MinHeap {
  constructor() {
    this.data = [];
  }

  // O(log n) — thêm vào cuối, "bubble up"
  insert(val) {
    this.data.push(val);
    this._bubbleUp(this.data.length - 1);
  }

  // O(log n) — lấy root, đặt phần tử cuối lên root, "sink down"
  extractMin() {
    if (this.data.length === 0) return undefined;
    const min = this.data[0];
    const last = this.data.pop();
    if (this.data.length > 0) {
      this.data[0] = last;
      this._sinkDown(0);
    }
    return min;
  }

  peek() {
    return this.data[0];
  } // O(1)

  _bubbleUp(i) {
    while (i > 0) {
      const parent = Math.floor((i - 1) / 2);
      if (this.data[i] >= this.data[parent]) break;
      [this.data[i], this.data[parent]] = [this.data[parent], this.data[i]];
      i = parent;
    }
  }

  _sinkDown(i) {
    const n = this.data.length;
    while (true) {
      let smallest = i;
      const left = 2 * i + 1,
        right = 2 * i + 2;
      if (left < n && this.data[left] < this.data[smallest]) smallest = left;
      if (right < n && this.data[right] < this.data[smallest]) smallest = right;
      if (smallest === i) break;
      [this.data[i], this.data[smallest]] = [this.data[smallest], this.data[i]];
      i = smallest;
    }
  }
}
```

### 5.3 Heapify — Build Heap O(n)

```javascript
// Build heap từ array — O(n) (KHÔNG phải O(n log n)!)
function buildMinHeap(arr) {
  // Bắt đầu từ node cuối có children, sinkDown
  for (let i = Math.floor(arr.length / 2) - 1; i >= 0; i--) {
    sinkDown(arr, i, arr.length);
  }
}
// Tại sao O(n)? Phần lớn nodes ở tầng dưới → ít work (sinkDown ngắn)
// Tổng work = Σ h_i = O(n)  (chứng minh bằng series)
```

### 5.4 Khi nào dùng Heap

| Use case              | Tại sao Heap                                  |
| --------------------- | --------------------------------------------- |
| Top K elements        | Maintain heap size K → O(n log k)             |
| Priority Queue        | Extract min/max O(log n)                      |
| Merge K sorted lists  | Min-heap of K elements                        |
| Median of data stream | Max-heap (lower half) + Min-heap (upper half) |
| Dijkstra's algorithm  | Priority queue for shortest path              |
| Task scheduling (OS)  | Priority-based scheduling                     |

## 6. Trie — Prefix Tree

```
Lưu tập hợp strings, tối ưu cho prefix search.

Insert: "cat", "car", "card", "dog"

         root
        /    \
       c      d
       |      |
       a      o
      / \     |
     t   r    g*
     *   |
         d*

  * = end of word (isEnd = true)

Search("car"):  root→c→a→r → isEnd? YES ✓
Search("ca"):   root→c→a → isEnd? NO (prefix, not complete word)
StartsWith("ca"): root→c→a → EXISTS ✓
```

```javascript
class TrieNode {
  constructor() {
    this.children = {}; // or Map() or Array(26)
    this.isEnd = false;
  }
}

class Trie {
  constructor() {
    this.root = new TrieNode();
  }

  insert(word) {
    let node = this.root;
    for (const c of word) {
      if (!node.children[c]) node.children[c] = new TrieNode();
      node = node.children[c];
    }
    node.isEnd = true;
  }

  search(word) {
    const node = this._traverse(word);
    return node !== null && node.isEnd;
  }

  startsWith(prefix) {
    return this._traverse(prefix) !== null;
  }

  _traverse(str) {
    let node = this.root;
    for (const c of str) {
      if (!node.children[c]) return null;
      node = node.children[c];
    }
    return node;
  }
}
// Insert/Search: O(m) — m = word length
// Space: O(TOTAL_CHARACTERS)
```

**Use cases**: Autocomplete, spell checker, IP routing (longest prefix match), contacts search.

## 8. Câu Hỏi Phỏng Vấn

**Q: BST worst case O(n) — làm sao khắc phục?**

> A: Dùng self-balancing BST (AVL hoặc Red-Black Tree). AVL maintain |height difference| ≤ 1 bằng rotations sau mỗi insert/delete → guarantee O(log n). Red-Black tree ít strict hơn nhưng ít rotations hơn → insert/delete nhanh hơn AVL. Databases dùng B-Tree (multi-way balanced) cho disk-friendly indexing.

**Q: Heap vs BST — khi nào dùng cái nào?**

> A: **Heap**: khi chỉ cần extract min/max nhanh (Priority Queue). Insert/Extract O(log n), nhưng search arbitrary element O(n). **BST**: khi cần search, insert, delete arbitrary elements đều O(log n), và cần sorted order (inorder traversal). Heap tốt hơn cho "top K" problems; BST tốt hơn cho range queries.

**Q: Build heap tại sao O(n) mà không phải O(n log n)?**

> A: Nếu insert từng element → O(n log n). Nhưng `heapify` bottom-up: bắt đầu từ nodes gần leaf (tầng dưới) → ít work per node. Tầng dưới cùng: n/2 nodes, sinkDown 0 bước. Tầng trên: n/4 nodes, 1 bước. Tổng = n/4 × 1 + n/8 × 2 + n/16 × 3 + ... ≈ n. (Taylor series sum).
